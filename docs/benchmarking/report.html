Original architecture contracts

Provider inputs → staged canonical events → reconciliation → owned immutable ledger → dated valuation/performance → evidence-backed insights → planning → AI explanation. Every stage can return unavailable with a specific reason. The mobile connector feeds the same import boundary; it never creates a second auth system.

ContractRequired meaning
Canonical eventOwner ID derived from session; owner-scoped account/folio; exact scheme/plan/option; event type; effective and posting dates; decimal-string units/amount; source row reference/hash; source schema version; correction/supersedes reference. PAN is not an authorization key.
Evidence statusSupported / partial / unavailable / conflicting; as-of and retrieved-at timestamps; method version; source IDs; missing requirements; coverage numerator/denominator. Used consistently from import to AI.
Ledger coveragePeriod start/end, opening units and cost evidence, statement closing units, reconciliation tolerance, unresolved events, supported asset scope. A snapshot is never silently promoted to a full ledger.
NAV/benchmark historyExact identity, effective mapping dates, value/date, provider/source, retrieval time, revision identity and quality status. No public feed automatically becomes a licensed commercial history service.
InsightObservation and calculation inputs separated from advice; method/threshold version, comparable cohort/window, measured result, source dates, confidence in data coverage and explicit abstention reasons.
Provider connectionOwner, provider connection ID, consent scope/status/expiry, approved data period, last successful/partial refresh, idempotency keys and revocation state. Never persist OTP or raw CAS in logs.
